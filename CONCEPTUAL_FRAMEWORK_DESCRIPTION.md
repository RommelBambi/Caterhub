# Conceptual Framework Description for Caterhub

The conceptual framework of CaterHub, as shown in the Input-Process-Output diagram, is logically divided into three distinct stages: Input, Process, and Output.

The Input section encompasses the required data for the system to function, categorized into User Context and Catering Context. The User Context includes the client's event data such as event date, guest count, user location (GPS coordinates or address), venue and delivery address, selected caterer and package, menu customization with dish selections, dietary restrictions and allergies, special requests, and payment preferences (deposit or full payment via GCash, PayMaya, or bank transfer). The Catering Context incorporates caterer profiles and business information, multiple service locations per caterer with service radius specifications (serviceRadiusKm), package offerings with price per head pricing, menu items organized into package sections and categories, package inclusions, and sample images.

The Process section illustrates how these inputs are actively handled by the system's core modules. The Service Discovery module finds matching caterers by utilizing geolocation-based search, applying address geocoding through the OpenStreetMap Nominatim API, calculating distances using the Haversine formula, filtering caterers based on service radius, and performing proximity-based matching. The Price Calculation module (Cost Engine) generates itemized quotes by calculating package prices (price per head × guests), computing delivery fees with a base fee of ₱500 for the first 5 kilometers and ₱50 per additional kilometer, accounting for transportation capacity requirements, and calculating deposit amounts (50% of total) and remaining amounts. The Booking module handles guest count confirmation, event date scheduling, booking data validation, storage of menu customizations and dietary restrictions, and management of booking status transitions (PENDING → CONFIRMED → ON_THE_WAY → COMPLETED, with DECLINED and CANCELLED statuses). The Payment Processing module processes all payments through Xendit payment gateway integration, generates payment links, processes multiple payment methods, tracks payment status in real-time, handles webhook events for automatic updates, and stores transaction details. The Notification module provides real-time booking updates, payment status notifications, and order updates to both customers and caterers.

The Output section details the final deliverables of the system. These include a confirmed booking contract containing booking ID, event details, guest count, venue address, selected package information, menu customization details, dietary restrictions, and comprehensive price breakdown (package subtotal, delivery fee, total amount, deposit, and remaining amount). The system generates payment receipts with transaction ID, payment method, amount, date, status (PAID, PENDING, or FAILED), and invoice documentation. Booking status updates provide transparent tracking throughout the booking lifecycle (PENDING, CONFIRMED, ON_THE_WAY, COMPLETED, DECLINED, CANCELLED). Service execution outputs ensure booking details, menu customizations, dietary restrictions, and delivery instructions are accessible to caterers. Finally, documentation and feedback mechanisms include a review and rating system (1-5 stars with text submissions, displayed on caterer profiles with average rating calculations) and booking history that maintains past bookings, payment records, and review history. All of these outputs provide event planners and caterers with a transparent, reliable source of information and a highly streamlined workflow.
