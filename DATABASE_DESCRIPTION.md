# Relational Database Description for Caterhub

The database begins at users and user_locations. The users table keeps the account information including role (customer, caterer, or admin), email, username, profile image, and suspension status for each account. Custom addresses saved with latitude and longitude are stored by the user_locations table and refer to a user, with each location having a name and primary flag. Partner_applications stores caterer registration information including business name, owner details, contact information, permit status, uploaded documents, and application status (Pending, Approved, or Rejected), linking to a user account. Caterer_profiles contain detailed business information for approved caterers including contact details, address, about description, and social media links, associating with a user account. Packages store catering packages created by caterers, containing name, price per head, menu sections with dishes, inclusions, and active status, linking to the caterer user. Bookings stores who booked which package, event date, guest count, delivery address, booking status (PENDING, CONFIRMED, ON_THE_WAY, DECLINED, COMPLETED, CANCELLED), payment information including deposit and remaining amounts, delivery fees, platform fees, and caterer payout amounts. Reviews allow users to rate a caterer or service between one to five stars, add commentaries and timestamps when posting, linking to bookings, users, and services. Favorites save which services users have marked as preferred. Caterer_subscriptions track subscription plans for caterers including plan type (monthly or yearly), amount, status (active, expired, cancelled, or pending_payment), payment information, and subscription period dates. Withdrawal_requests store caterer requests to withdraw earnings including amount, payment method, payment details, status, and Xendit payout tracking information. Caterer_monthly_gmv records monthly gross merchandise value for each caterer including total GMV, completed orders count, and fee tier calculations for the next month. Payment_webhooks save all payment webhook events from Xendit including event type, payment details, status, and processing information. Terms_conditions store different versions of terms and conditions with version number, title, content, effective date, and active status. User_terms_acceptance tracks when users accept specific terms versions including acceptance timestamp, IP address, and user agent. Support_tickets save user support requests including subject, description, type, status, priority, admin notes, and resolution information, optionally linking to bookings. Notifications store all alerts sent to users including title, message, type, related entity ID, read status, and timestamps. All tables are using foreign keys that will keep data associating throughout the system.
